# ADR-003: MVC

# 1. Contexto
O sistema da biblioteca será desenvolvido como um monólito modular (ADR1), com arquitetura hexagonal (ADR2). Falta definir como estruturar internamente a lógica da aplicação e interação com o usuário.

# 2. Problema ou forças envolvidas
As regras de negócios devem ser isoladas (RNF4); o padrão escolhido deve usar as portas e adaptadores do modelo hexagonal (não criar um segundo estilo de comunicação); o núcleo deve ser testável sem a interface real.


# 3. Alternativas consideradas
MVC separa o modelo, a visão e os controladores; lógica de interface embutida nos controllers; MVP é similar ao MVC mas com uma camada adicional ‘presenter’ entre a visão e os controladores.

# 4. Decisão
MVC foi escolhido

# 5. Consequências positivas
Separação clara das responsabilidades dos controladores; isolamento das regras de negócio e uso de padrões GRASP

# 6. Consequências negativas, custos ou riscos
Aumento de número de classes e indireção (complexidade); mesmo sendo um padrão conhecido pode haver curva de aprendizagem para a equipe.
