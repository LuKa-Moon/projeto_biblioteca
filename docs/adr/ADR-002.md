# ADR-003: Arquitetura Hexagonal

# 1. Contexto
Deve ser criado um sistema que permita consulta, reserva, empréstimo, devolução e alteração de livros, além de notificações de atraso e vencimento de reserva.

# 2. Problema ou forças envolvidas
Problema ou forças envolvidas: O sistema deve ser capaz de se integrar com o sistema de autenticação da empresa e com um mecanismo de notificação a ser escolhido. Além disso, as aplicações de empréstimo, consulta e alteração não devem estar acopladas entre si. 

# 3. Alternativas consideradas
A: Arquitetura Hexagonal
B: Clean Arquitecture 

# 4. Decisão
Foi escolhida a arquitetura hexagonal, pois julgou-se que portas e adaptadores funcionava melhor para o problema dado do que a lógica vertical da Clean. Serão construídas portas e adaptadores para a autenticação, para a notificação e para as aplicações. 

# 5. Consequências positivas
Construção e depuração do núcleo se torna independente dos recursos externos e das aplicações. 

# 6. Consequências negativas, custos ou riscos
Custo: Pode haver uma curva de aprendizagem maior para a equipe.
