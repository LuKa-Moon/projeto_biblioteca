# ADR-001: Monólito Modular

# 1. Contexto
Deve ser criado um sistema para a biblioteca de um campus universitário.

# 2. Problema ou forças envolvidas
A equipe tem limitações técnicas (falta de experiência com sistemas distribuídos e baixa maturidade DevOps no geral), além de ser pequena.

# 3. Alternativas consideradas
a. SOA

b. Microsserviços

c. Monólito Modular

# 4. Decisão
Monólito modular foi escolhido, devido à sua menor complexidade, manutenibilidade mais simplificada (importante para uma equipe pequena) e menor curva de aprendizado.

# 5. Consequências positivas
Menos complexo, depuração centralizada, manutenção mais simples, requer menos maturidade operacional da equipe, menor custo de desenvolvimento.

# 6. Consequências negativas, custos ou riscos
A escalabilidade e o desempenho são prejudicados, dado que sistemas distribuídos permitem espalhar a carga entre várias máquinas, porém esses pontos não foram interpretados como cruciais para este caso.
